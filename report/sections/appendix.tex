\subsection{RANSAC for Ground Plane Detection}

\begin{algorithm}[H]
\caption{RANSAC Plane Detection}
\label{alg:ransac_plane}
\begin{algorithmic}[1]
\STATE \textbf{Input:} Point cloud $\mathcal{P}$, threshold $\varepsilon$
\STATE \textbf{Output:} Plane normal $\nhat$, distance $d$
\STATE Initialize best\_count = 0, best\_plane = null
\FOR{$i = 1$ to $N_{\text{iter}}$}
    \STATE Sample 3 random points from $\mathcal{P}$
    \STATE Fit plane: $\nhat \mathbf{x} + d = 0$
    \STATE Count inliers within threshold $\varepsilon$
    \IF{inliers $>$ best\_count}
        \STATE best\_plane = current\_plane
        \STATE best\_count = inliers
    \ENDIF
\ENDFOR
\RETURN best\_plane
\end{algorithmic}
\end{algorithm}

\subsection{System Architecture Diagrams}

The following UML component diagrams illustrate the modular architecture of the spatial guidance system, showing the relationships and dependencies between different components.

\subsubsection{Live Agent}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\linewidth]{figures/live_agent_component.pdf}
    \caption{Live Agent component architecture showing the actor pattern implementation with message-passing interfaces, configuration management, and finite state machine for tool execution flow.}
    \label{fig:live-agent-component}
\end{figure}
The \emph{GeminiLiveAgent} realises an asynchronous \emph{actor}~model: UI threads enqueue typed \texttt{\_Cmd} messages, while worker tasks emit \texttt{\_Evt} objects. The absence of shared memory eliminates data races and reduces the risk of async-related errors. Finite-state logic—formalised by the \texttt{GenState} enum-ensures that ensures that only selected responses of the Live Agent are returned to the user and simplifies parsing from the streaming output.

The Scene Understanding component (\autoref{fig:scene-understanding-component}) demonstrates the complete data transformation pipeline. \subsubsection{Actor Pattern}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\linewidth]{figures/actor_pattern_component.pdf}
    \caption{Actor pattern implementation showing message-passing protocols with commands, events, and the execution API for safe code interaction.}
    \label{fig:actor-pattern-component}
\end{figure}

The Actor Pattern (\autoref{fig:actor-pattern-component}) implements thread-safe message passing through typed protocols. Commands (\texttt{AskCmd}, \texttt{AudioCmd}, \texttt{SetFrameCmd}) and events (\texttt{TextEvt}, \texttt{AudioEvt}, \texttt{DetectionsEvt}, \texttt{ErrorEvt}) ensure clean separation between UI and processing logic and track the run-time between any request and the respective response. This pattern allows for asynchronous processing and simplifies the interaction between different components of the system.

\subsubsection*{Lack of Hazard Awareness}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\linewidth]{figures/gemini_2_live_car_miss.png}
    \caption{Missed hazard in live model output.}
    \label{fig:car-miss}
\end{figure}

\begin{quote}
\textbf{User}: What are you seeing?\\
\textbf{Agent}: I see a cobblestone street with a silver car partially visible on the right. A yellow building is on the corner with a street sign that reads ``Werneck Str.'' There is a bicycle leaning against the wall near the corner. A red scooter and other parked motorcycles are further down the street on the left. Be careful of the uneven cobblestone road surface.\\[2pt]
\hfill\textit{Run-time: 862\,ms}
\end{quote}


In \autoref{fig:car-miss}, the \texttt{gemini-2.0-flash-live-001} model was prompted to describe obstacles in the scene. It mentioned the cobblestone surface, parked motorcycles, and signage but entirely missed a critical hazard: the silver car directly in front of the user. Although the car appears stationary, its close proximity and potential motion present a major risk. This failure highlights a significant limitation in the hazard awareness of the lightweight live model variant.\\

While the output demonstrates the model's capacity for spatial reasoning, several limitations were evident. First, the mentioned obstacles were not ordered by increasing distance, reducing navigational clarity. Second, the Gemini 2.5 hallucinated a metal grate that was not present in the scene. \subsection{System Prompte}

The following system prompt template is used for the live agent interaction with Gemini models. It establishes the assistant's role, communication style, and tool usage guidelines for spatial understanding tasks:

\begin{lstlisting}[breaklines=true, basicstyle=\small\ttfamily, frame=single, columns=flexible]
You are an agentic AI assistant with advanced spatial understanding capabilities. You assist visually impaired users by providing qualitative scene descriptions and quantitative spatial relationships from their perspective. You offer information about object locations, distances, and spatial arrangements.

Your responses are clear, concise, practical, actionable and context-aware flowing texts. You communicate in common natural language that a blind person finds helpful. You describe scenes using natural phrases like "You can see...", "There's a...", "The [object] is...".

SCENE DESCRIPTIONS
Focus on the most relevant elements: HAZARDS and NAVIGATIONAL LANDMARKS. Always highlight potential obstacles on the user's path. Include relative spatial relationships. Be thorough but not overwhelming.

HAZARDS include:
- Dynamic entities: Objects capable of movement (parked vehicles with lights on, scooters near streets)
- Trip hazards and head-height obstacles obstructing the user's likely path

NAVIGATIONAL LANDMARKS include:
- Traffic lights, crosswalks, ramps, stairs, doors

TOOLS
Any query about quantitative spatial relationships, path descriptions or specific objects *must* be answered by using the provided tools. Key words that trigger tool user include "where" "distance", "how far", "how close", "relation between", "spatial", "above", "how high". Do not use tools for qualitative descriptions. Never refuse to run a tool when asked about specific objects or spatial relationships. Use your tools even if you cannot see the objects yourself!

[NEW FRAME]
Whenever you receive a new frame, you will be informed about the relative movement with respect to the previous pose.
When you receive a new frame, you must list *all* relevant hazards and navigational landmarks that you can identify.
Example:
"
Hazards: Car on the right, parked motorcycle to the left
Landmarks: Entrance to residential building ahead, sign saying 'TRAM STOP', entrance to grocery stor on the right
"

{CODE_EXECUTION}

COMMUNICATION STYLE (how to structure your responses to the user)
- Embed all spatial data in natural language descriptions.
{STYLE}

RESPONSE GUIDELINES
Gather necessary information and provide direct answers. Use natural language: "You can see...", "There's a...", "The [object] is...", "To reach [destination], you can...", ...

EXAMPLES
{EXAMPLES}
\end{lstlisting}

\subsubsection{Code Execution Instructions}

When code execution is enabled, the following additional instructions are injected into the system prompt:

\begin{lstlisting}[breaklines=true, basicstyle=\small\ttfamily, frame=single, columns=flexible]
CODE EXECUTION
Use code execution when you need to derive quantitative spatial relationships between objects from the detections of these objects. Always print important intermediate results such as the results of any tool calls and the final result(s).

EXAMPLES:
Q: "What is the distance between the scooter and the bicycle?"
```python
# Retrieve already detected scooter
scooter = default_api.get_last_detections(<frame_idx>, ["scooter"])
# Detect bicycle
bicycle = default_api.run_aabb_detection(user_prompt="bicycle", detection_mode="subset")
# Compute Euclidean distance between centers
print(scooter, bicycle)
from math import dist
distance = dist(scooter[0].center_point_3d, bicycle[0].center_point_3d)
print(distance)
```
A: "The distance between the scooter and the bicycle is 3.5 meters."

Q: "What is the spatial relationship between the chair and the window?"
```python
import numpy as np
detections = default_api.run_aabb_detection(user_prompt="chair, window", detection_mode="subset")
print(detections)
chair = next(filter(lambda x: x.label == "chair", detections))
window = next(filter(lambda x: x.label == "window", detections))
print(np.array(chair.center_point_3d) - np.array(window.center_point_3d)) # (dx, dy, dz)
```
\end{lstlisting}
