The \texttt{LiveAgent} orchestrates user interaction and tool calls, \texttt{GeminiAABBDetSeg} produces zero-shot detections, \texttt{GeomProc} enriches them with 3-D geometry, and \texttt{DetCache} maintains temporal coherence across frames.}
    \label{fig:system-arch}

The architecture follows an asynchronous \emph{actor pattern} in which each component runs in its own task and exchanges typed messages:
\begin{enumerate}
    \item \textbf{LiveAgent} receives user queries (spoken or textual) and decides, through a finite-state machine, whether  qualitative reasoning suffices or quantitative tool calls are required.
    \item \textbf{GeminiAABBDetSeg} converts an RGB image into raw axis-aligned bounding boxes (AABBs), segmentation masks, and class labels via zero-shot prompting of the Gemini~2.5 model (see Fig.~\ref{fig:gemini-seq}).
    \item \textbf{GeomProc} projects the 2-D detections into metric 3-D space, estimates per-object depth, yaw, and height, and packages the results in an \texttt{AABBDetection} record (Algorithms~\ref{alg:gemini_detection}–\ref{alg:mask_processing}).
    \item \textbf{DetCache} transforms previous detections into the current ego frame and serves them to the agent, enabling multi-view coherence.
\end{enumerate}
All data flow is strictly typed using \textsc{Pydantic} models, ensuring schema validation at every interface.


\subsection{Spatial Processing Pipeline}

The following steps describe how a single RGB-D frame is transformed into structured 3D detections that can be used for navigation.

\subsubsection{Dataset Loader}
The \texttt{StrayDataset} provides frames through its \texttt{\_{}\_{}getitem\_{}\_} method. It loads the RGB image \(\I\), the depth map \(\Z\), adapts the intrinsics \(\K\), retrieves the camera pose \(\T_{WC}\) and optionally estimates the ground plane \((\nhat,d)\). The fields are returned in a \texttt{DatasetOut} structure.

\begin{algorithm}[H]
\caption{Dataset Loader}
\label{alg:dataset_loader}
\begin{algorithmic}[1]
\STATE \textbf{Input:} frame index \(i\)
\STATE \textbf{Output:} DatasetOut\((i,\I,\Z,\K,\T_{WC},(\nhat,d))\)
\STATE \(\I \gets \text{load\_rgb}(i)\)
\STATE \(\Z \gets \text{load\_depth}(i)\)
\STATE \(\K \gets \text{adapt\_intrinsics}(i)\)
\STATE \(\T_{WC} \gets \text{get\_pose}(i)\)
\IF{ground plane enabled}
    \STATE \((\nhat,d) \gets \text{estimate\_ground\_plane}(\I,\Z,\K)\)
\ENDIF
\RETURN DatasetOut\((i,\I,\Z,\K,\T_{WC},(\nhat,d))\)
\end{algorithmic}
\end{algorithm}

Estimating the height of an object relative to the ground plane employs the hessian normal form of the plane.
When enabled, the ground plane is estimated via RANSAC following the procedure described in~\autoref{alg:ground_plane}.

The depth map is converted to a point cloud, and RANSAC is applied to find the best-fitting plane. The resulting plane normal \(\nhat\) and distance \(d\) are used to describe the ground plane in the world frame. The plane equation is given by

this allows
\begin{equation}
    \label{eq:ground_plane}
    \nhat^{\top}\mathbf{x} + d = 0 .
\end{equation}

\subsubsection{Gemini Detection}
The RGB frame is sent to Gemini, yielding raw 2-D boxes and segmentation masks. Each detection is processed as follows.
A resized RGB image, the detection \texttt{mode}, and an \texttt{agent\_prompt} are passed to Gemini~2.5.  The VLM returns JSON conforming to a minimal schema (\textit{label}, \textit{box\_2d}, \textit{mask}).  Malformed or schema-violating outputs will trigger a validation error in the datacentric pipeline, where the validation is performed within the \emph{validator} methods of the respective \textsc{Pydantic} models.

\subsubsection{Geometric Processing}
The detections and segmentations provided by Gemini are processed to extract 3-D attributes such as depth, yaw, and height. The geometric processing pipeline is illustrated in \autoref{fig:geom-pipeline} and described in Algorithm~\ref{alg:gemini_detection}.

\begin{algorithm}[H]
\caption{Processing Gemini Detections}
\label{alg:gemini_detection}
\begin{algorithmic}[1]
\STATE \textbf{Input:} bbox \(\bbox\), mask \(\Ms\), ground plane \((\nhat,d)\)
\STATE \textbf{Output:} enriched detection attributes
\STATE Scale \(\bbox\) from \([0,1000]\) to pixel coordinates
\STATE Resize \(\Ms\) to \(\bbox\)'s region
\STATE Erode \(\Ms\) and compute depth statistics
\STATE Compute 3-D centers from \(\bbox\) and \(\Ms\)
\STATE Derive BEV rotation
\STATE Compute object height using ground plane
\end{algorithmic}
\end{algorithm}

\subsubsection{Mask Processing}

\begin{algorithm}[H]
\caption{Process Mask: Thresholding, Resizing, and Erosion}
\label{alg:mask_processing}
\begin{algorithmic}[1]
\STATE \textbf{Input:}
\STATE \quad Prob. mask \(\hat{\mathbf{M}} \in [0,1]^{h \times w}\)
\STATE \quad AABB \(\mathbf{b} = (x_0, y_0, x_1, y_1)\)
\STATE \quad Image size \(H \times W\)
\STATE \quad Threshold \(\theta \in (0,1)\)
\STATE \quad Structuring element \(\mathbf{S}^{(3)} \in \{0,1\}^{3 \times 3}\)
\STATE \textbf{Output:}
\STATE \quad Eroded binary mask \(\mathbf{M}' \in \{0,1\}^{H \times W}\)
\STATE \(\mathbf{M} \leftarrow \text{AlignWithBoundingBox}(\hat{\mathbf{M}}, \mathbf{b}, H, W)\) \COMMENT{Resize \& align w/ AABB}
\STATE \(\mathbf{M} \leftarrow [\mathbf{M} \geq \theta]\) \COMMENT{Threshold to binary mask}
\STATE \(\mathbf{M}' \leftarrow \mathbf{M} \ominus \mathbf{S}^{(3)}\) \COMMENT{Erode mask}
\RETURN \(\mathbf{M}'\)
\end{algorithmic}
\end{algorithm}

\subsubsection{Estimating Clock Direction}
Given a 3D point \( \pc \) in camera coordinates the yaw angle \(\psi_{\text{deg}}\) and clock position \(\psi_{\text{clk}}\) are computed as follows:

$$
\begin{aligned}
\psi_{\text{deg}} &= \arctan2\left(x^c, z^c\right) \cdot \frac{180°}{\pi} \\
\psi_{\text{clk}} &= \left\lfloor \frac{\psi_{\text{deg}}}{30°} + 0.5 \right\rfloor \bmod 12

\subsubsection{Estimating Height Relative to the Ground}
With ground plane parameters \((\nhat,d)\) the height of a point \(\mathbf{p}\) is
\begin{equation}
h = \nhat^{\top} \mathbf{p} + d.
\label{eq:height}
\end{equation}

\subsubsection{Describing Relative Motion}
% Provide the LiveAgent with description of relative movement, when frames change:


% LiveAgent will receive a system message with
% relative description
% overview of all previous detections
% It will then do internal “reasoning”, listing potentially relevant entities in the scene
% Previous detections can be retrieved in current ego frame.


The following steps describe how a motion between two SE(3) \emph{ego poses} is described such that it can be injected into the model context. The transformation from one pose \(\T_A\) to another \(\T_B\) is given by:
\begin{equation}
\T_{rel} = \T_B \T_A^{-1},\quad
d = \|\boldsymbol{\tau}_{rel}\|,\quad
\psi = \operatorname{atan2}(-R_{32}, R_{11}).
\label{eq:relative_motion}
\end{equation}

The translation vector \(\boldsymbol{\tau}_{rel} = \T_{rel}[:3, 3]\) is the relative motion in meters, and \(\psi\) is the \emph{yaw}-rotation around the \emph{vertical} axis. \( R_{32} \), and \( R_{11} \) contain the negative sine and cosine of the rotation angle, respectively.\\
We then provide the model with a system message, that describes the relative motion, and also provide it with an overview of all cached detections from previous frames.


\subsubsection{Resulting Structure}
After processing, all fields are stored in \texttt{AABBDetection}: normalized box, mask, depth statistics, 3-D center, rotation in degrees and clock hours, and height from the ground plane.  These detections across frames are transformed into the ego frame for path planning.
